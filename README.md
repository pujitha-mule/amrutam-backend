# Amrutam Telemedicine Backend

A modular FastAPI backend for a telemedicine workflow, using PostgreSQL, SQLAlchemy's async API, Alembic migrations, Docker, and automated tests.

> **Project status:** This repository is an implementation/demo, not a production certification. The tests and local workflow validate core behavior; the 100k-consultations/day, p95 latency, and 99.95% availability targets still require load testing and a deployed, highly available environment.

## Features

- User authentication and role-aware API access
- Doctor discovery/availability and consultation booking
- Consultation state transitions
- Prescription issuance and patient prescription listing
- PostgreSQL persistence and Alembic migrations
- Idempotent booking support
- Audit logging and structured application logging
- Health/readiness and Prometheus-style metrics endpoint
- Docker configuration and GitHub Actions CI
- Automated tests

Use the live OpenAPI document generated by FastAPI at `/openapi.json` and the interactive API explorer at `/docs` when the application is running.

## Local setup (PowerShell)

Run commands from the repository root.

1. Create and activate a virtual environment:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

2. Install dependencies:

   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

3. Create a local environment file from the example:

   ```powershell
   Copy-Item .env.example .env
   ```

   Edit `.env` for your local PostgreSQL and Redis services. Never commit `.env` or real credentials.

   Example development-only values (replace for your machine):

   ```env
   DATABASE_URL=postgresql+asyncpg://amrutam:amrutam@localhost:5432/amrutam
   REDIS_URL=redis://localhost:6379/0
   JWT_SECRET=replace-with-a-long-random-secret
   JWT_REFRESH_SECRET=replace-with-a-different-long-random-secret
   MFA_ENCRYPTION_KEY=replace-with-a-valid-key-for-your-config
   PAYMENT_WEBHOOK_SECRET=replace-with-a-random-webhook-secret
   ENV=dev
   ```

4. Create the database and database role in PostgreSQL if they do not already exist. Ensure the database URL matches `.env`.

5. Apply migrations:

   ```powershell
   alembic upgrade head
   ```

6. Start the API:

   ```powershell
   uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
   ```

7. Open:
   - API docs: `http://127.0.0.1:8000/docs`
   - OpenAPI JSON: `http://127.0.0.1:8000/openapi.json`
   - Liveness/health: `http://127.0.0.1:8000/health`
   - Readiness: `http://127.0.0.1:8000/health/ready`
   - Metrics: `http://127.0.0.1:8000/metrics`

   Confirm endpoint paths in the running app if your branch has customized health routes.

## Docker setup

Review `compose.yaml` and `.env.example` first, then run:

```powershell
docker compose up --build
```

Stop services with `Ctrl+C`, then `docker compose down`. Do not use production credentials in local Compose.

## Database migrations

```powershell
alembic current
alembic upgrade head
```

For a new migration after a model change:

```powershell
alembic revision --autogenerate -m "describe schema change"
```

Review generated migrations before applying them. Never rely on autogeneration without inspecting the SQL and downgrade behavior.

## Core workflow smoke test

The implemented local smoke test used these steps:

1. Log in as a doctor and a patient.
2. Find/create a doctor availability slot.
3. Book a consultation using an idempotency key; repeat the same request and confirm the same booking is returned.
4. Move the consultation through the permitted state transitions.
5. Issue a prescription only after the consultation is completed.
6. Fetch the prescription by ID as the authorized doctor.
7. Fetch the patient's prescription list as the patient.

Use synthetic demo data only. Do not put real patient information or real credentials in screenshots, logs, or the demo recording.

## API schema

FastAPI generates OpenAPI from registered routes and Pydantic schemas:

- Interactive docs: `/docs`
- Raw OpenAPI: `/openapi.json`

For a static schema file, while the service is running:

```powershell
Invoke-WebRequest http://127.0.0.1:8000/openapi.json -OutFile openapi.json
```

Commit the generated file only after checking that it contains no internal-only routes or environment-specific data.

## Security notes

- `.env`, tokens, keys, and local logs must not be committed.
- `.env.example` must contain placeholders only.
- Use HTTPS/TLS at the ingress in production.
- Use a secrets manager, rotate credentials, and apply least-privilege database permissions.
- Keep dependencies patched and review CI/security scan results.
- This project does not claim regulatory certification. Conduct a privacy/legal review before handling real clinical data.

See [Security and Threat Model](docs/SECURITY.md).

## Scale and reliability targets

The assignment targets 100,000 consultations/day, read p95 below 200 ms, write p95 below 500 ms, and 99.95% availability. These are **design targets, not measured results**. Validate them with representative load tests, query plans, capacity planning, multi-zone deployment, failover exercises, and SLO monitoring before claiming they are met.
